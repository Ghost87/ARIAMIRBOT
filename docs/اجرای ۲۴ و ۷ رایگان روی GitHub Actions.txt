🧠 معماری یک نگاه
────────────────────────────────────────────────────────────────
چون ریپو PUBLIC است، رانر استاندارد GitHub Actions کاملاً رایگان و
نامحدود است. برای همین سورس کد را نمی‌توان باز گذاشت → کل سورس در
«src.enc» با AES-256 رمز شده و فقط با سکرت DECRYPT_KEY اجرا می‌شود.
دو ورک‌فلو کار می‌کنند:

   🤖 run-bot.yml      → ربات را اجرا می‌کند (دستی تا ۳۵۶ دقیقه،
                         یا خودکار هر ۶ ساعت: ۳۴۵ دقیقه)
   🐕 bot-watchdog.yml → هر ۳۰ دقیقه چک می‌کند؛ اگر ربات پایین بود،
                         خودکار دوباره روشنش می‌کند

ران بعدیِ run-bot در صف می‌ماند و دقیقاً وقتی قبلی تمام شد شروع
می‌شود ⇒ چرخهٔ بی‌وقفهٔ ۲۴/۷ بدون تداخل پولینگ تلگرام.

۱) سکرت‌ها — Settings → Secrets and variables → Actions
────────────────────────────────────────────────────────────────
   ┌──────────────────┬─────────────────────────────────────────┐
   │ DECRYPT_KEY      │ 🔑 رمز فایل‌ها (کلید رمزگشایی src.enc    │
   │                  │ که به شما داده شده — اجباری)            │
   ├──────────────────┼─────────────────────────────────────────┤
   │ BOT_TOKEN        │ توکن ربات از @BotFather (اجباری)        │
   ├──────────────────┼─────────────────────────────────────────┤
   │ ADMIN_USERNAME   │ یوزرنیم ورود به پنل /admin              │
   ├──────────────────┼─────────────────────────────────────────┤
   │ ADMIN_PASSWORD   │ پسورد ورود به پنل (قوی انتخاب شود)      │
   ├──────────────────┼─────────────────────────────────────────┤
   │ ADMIN_USER_IDS   │ آیدی عددی ادمین(ها) با کاما             │
   ├──────────────────┼─────────────────────────────────────────┤
   │ ADMIN_GROUP_ID   │ آیدی گروه ادمین — سفارش‌ها/فیش‌ها        │
   │                  │ (با -100 شروع می‌شود)                   │
   ├──────────────────┼─────────────────────────────────────────┤
   │ GH_PAT           │ (اختیاری) توکن شخصی برای نمایش وضعیت    │
   └──────────────────┴─────────────────────────────────────────┘

۲) شروع چرخهٔ ۲۴/۷ (فقط یک‌بار)
────────────────────────────────────────────────────────────────
۱. Actions → «🤖 Run ARIAMIR Orders» → Run workflow
۲. دقیقه را ۳۵۶ بگذار و سبزش کن.
۳. تمام! از اینجا:
   • این ران ۶ ساعت روشن است؛ ران بعدی خودش صف می‌ایستد.
   • نگهبان هر ۳۰ دقیقه سلامت را چک و در صورت نیاز احیا می‌کند.
نکته: بین دو چرخه حدود ۱–۲ دقیقه وقفهٔ بوت رانر است؛ پیام‌های
کاربران در صف تلگرام می‌مانند و بعد تحویل داده می‌شوند.

۳) خاموش‌کردن کامل (موقت)
────────────────────────────────────────────────────────────────
۱. Actions → Workflows → «🐕 Bot Watchdog» → ⋯ → Disable workflow
۲. از لیست Recents، ران جاری run-bot را Cancel کن.
(برگرداندن: Enable نگهبان + یک Run دستی.)

۴) حافظهٔ پایدار (db-backup)
────────────────────────────────────────────────────────────────
• در پایان هر اجرا، دیتابیس رمزشده (bot.db.enc) به برنچ db-backup
  پوش می‌شود؛ شروع بعدی همان را رمزگشایی و ادامه می‌دهد.
• چون رمزشده است، برنچ db-backup در ریپوی پابلیک هم امن است — بدون
  DECRYPT_KEY قابل خواندن نیست.
• شروع از صفر: یک Run دستی با wipe_db=true.
• بکاپ دستی: Actions → ران موردنظر → Artifacts → ariamir-orders-data

۵) اجرا روی VPS (جایگزین Actions — ۲۴/۷ واقعی مداوم)
────────────────────────────────────────────────────────────────
اگر VPS داری، این روش پایدارتر از Actions است:
۱. ریپو را کلون یا زیپ رمزدار را باز کن (پیام ۵۷ گروه Arsourcer).
۲. رمزگشایی:   DECRYPT_KEY='رمز فایل‌ها' ./decrypt.sh
   (اگر از زیپ رمزدار استفاده می‌کنی، سورس باز است و نیاز نیست.)
۳. cd decrypted → venv + pip + cp .env.example .env و پر کردنش
۴. اجرای دائمی: sudo cp deploy/ariamir-orders.service /etc/systemd/system/
   سپس: systemctl enable --now ariamir-orders
۵. لاگ: journalctl -u ariamir-orders -f
